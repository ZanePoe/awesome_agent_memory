# i18n layout

Every catalogue ships the same reading surface in five languages: English (default, repo root), Simplified Chinese, Spanish, Hindi and French (top five languages by total speakers).

## Output tree

| Path | Content |
| --- | --- |
| `README.md`, `docs/projects.md`, `docs/rankings.md`, `docs/<static>.md`, `CONTRIBUTING.md` | English (default) |
| `locales/<lang>/README.md`, `locales/<lang>/docs/projects.md`, `locales/<lang>/docs/rankings.md`, `locales/<lang>/docs/<static>.md`, `locales/<lang>/CONTRIBUTING.md` | one mirror per locale in `zh`, `es`, `hi`, `fr` |

`locales/<lang>` mirrors the root layout, so relative links inside a mirror (`docs/projects.md`, `CONTRIBUTING.md`) are written once in the templates. Every `{R}` in a generated file comes from one function, `prefix(locale, depth)`, which counts the `../` steps from that file to the repository root: `depth=0` for files at the language root (`README.md`, English `""`, mirror `"../../"`) and `depth=1` for files in `docs/` (English `"../"`, mirror `"../../../"`), so generated links into `LICENSE`, `data/` and `record/` are written once per template.

Hand-written prose resolves from its own directory, which is one level deeper than the README, so the counts differ — `check_links()` enforces this:

| File | Link into repository root |
| --- | --- |
| `docs/research.md` (English) | `../research/search-log.json` |
| `locales/<lang>/docs/research.md` | `../../../research/search-log.json` |
| `CONTRIBUTING.md` (English) | `data/projects.json`, `record/` |
| `locales/<lang>/CONTRIBUTING.md` | `../../data/projects.json`, `../../record/` |

`docs/readme-intro.md` is the one prose file listed in `build.INLINE`: it is inlined into the README and therefore resolves from the locale root, writing `docs/projects.md` and `CONTRIBUTING.md` in both layouts.

Language switcher: the generated README of every locale starts with the same line linking all five.

## Source of truth

| File | Role |
| --- | --- |
| `data/projects.json` | canonical review data, written in Chinese; also the fallback for `zh` |
| `locales/<lang>/ui.json` | `language`, `language_name`, `list_separator` plus category, scope, licence-status, tier, mode labels, table headers, section titles and paragraph templates |
| `locales/<lang>/entries.json` | `repo → {description, boundary, license_label, license_note}` for that language, plus an optional `name` override (only needed when the canonical display name contains Chinese characters; every `name` in this catalogue is already Latin-script, so none is required) |
| `locales/<lang>/docs/*.md`, `locales/<lang>/CONTRIBUTING.md` | hand-written static prose per locale |
| `locales/zh/ui.json` | the Chinese strings `build.py` used to hard-code; it is the translation source for every other locale |

`zh` has no `entries.json` — `build.py` falls back to `data/projects.json`. Every other locale must provide one entry per repository, or `validate()` fails.

## Translation rules

- Keep facts identical to the Chinese source. Do not add claims, benchmarks or guarantees.
- Leave unchanged: repository names, project names, URLs, file paths, commit SHAs, license identifiers (MIT, Apache-2.0, PolyForm, BSL …), star counts, dates, model names, code blocks, Markdown table shape.
- Literal search keywords inside `docs/research.md` stay verbatim; only the surrounding prose and table headers are translated. That file is the one exception to the no-Chinese rule for non-`zh` locales, and `tests/test_i18n.py` enforces the narrow form of the exception: Chinese may appear only in Markdown table rows or inside backticks, never in prose lines.
- `record/` is an audit trail in the language it was written in; each locale links to it and says so (`records_note`).
