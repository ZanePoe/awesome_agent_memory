# 2026-11-25 合集多语言化

本仓库按 `awesome_ai_video_creation` 已合入的多语言框架移植：英语为默认（仓库根 `README.md`、`docs/`、`CONTRIBUTING.md`），中文与西班牙语、印地语、法语以完整镜像放在 `locales/<lang>/`。语言选择依据是总使用人数前五（英语、中文普通话、印地语、西班牙语、法语）。

## 移植内容

- `scripts/build.py`：中文 UI 常量全部外置到 `locales/<lang>/ui.json`（`categories`、`scopes`、`license_status`、`modes`、`tiers`、`tags`、`headers`、`sections`、`templates` 共 12 个顶层键）；条目文案读 `locales/<lang>/entries.json`，`zh` 回落 `data/projects.json`，因此本仓库没有 `locales/zh/entries.json`（90 个规范名均不含 CJK，无需显示名覆盖）。
- 生成物：`README.md`、`docs/projects.md`、`docs/rankings.md` 各 5 份（英文在根，其余在 `locales/<lang>/`），共 16 个文件；`data/rankings.csv` 语言中立化，`maintenance_status` 中文列改为 `maintenance_tier` 0–3。
- 静态文档：英文改写根 `docs/{readme-intro,taxonomy,methodology,research}.md` 与 `CONTRIBUTING.md`，中文原件移入 `locales/zh/docs/`，es/hi/fr 各一份；`docs/research.md` 是唯一允许保留字面中文的译文文件（检索关键词与内容工厂查询串逐字保留，且只能出现在表格行或反引号内）。
- 门禁：`validate()` 增加 locale 覆盖、模板键与占位符同形、非 `zh` 语言无 CJK、条目四字段非空、静态文档存在性检查；`check_links()` 按「文件自身目录」解析相对链接，并把该 locale 的生成物路径视为预期目标；`tests/test_i18n.py` 断言五语产物齐全、切换行链接可达、页内锚点有效、CSV 语言中立，并在删除任一 locale 条目时报错。
- CI：`.github/workflows/refresh.yml` 的提交范围扩到 `README.md docs locales`。

## 移植时修掉的框架缺陷

1. `render_all` 用 `str(path(...))` 读取以 `.as_posix()` 写入的键，Windows 上必 `KeyError: 'locales\zh\README.md'`；改为同一个 `readme` 变量。
2. `anchor()` 丢弃 Unicode 组合符，天城文标题生成的锚点与 GitHub 实际 slug 不一致（`श्रेणी सूची` → `शरण-सच`），补 `unicodedata.category(ch) in ('Mn','Mc','Me')` 并 `import unicodedata`。
3. 「不留汉字」判定只用 `[\u4e00-\u9fff]`，漏掉 `、`、`「」`、全角括号；统一为 `build.CJK` 常量，`validate()` 与测试共用。
4. `test_csv_is_language_neutral` 断言 `header[-2]=='maintenance_tier'`，实际 14 列里倒数第二列是 `score`，断言恒假；改为按列名取索引。

## 事实更正

`docs/research.md` 原有两处写死当时的收录数（87），与实际 90 条不一致；中英文与三种译文统一改为不依赖收录数量的表述（「全部项目」「合集中的项目」）。来源数与台账数字（72 个不同来源、847/174/261）属调研事实，未改动。

## 已知偏差

- 本仓库 README 的「靠前的项目」分隔符由 `、` 提为 `ui.json` 的 `list_separator`，`zh` 保持 `、`，其余语言为 `, `。
- 译文由模型生成，未经母语者复核；术语取舍见各 locale 交付记录，发现误译直接改对应 `locales/<lang>/` 文件。
- `record/` 与 `research/` 保持撰写时原文，不做机器翻译。
