# 2026-11-25 上游仓库消失与更名（M-flow 移除、Membase 更名）

触发点：每日 `Refresh GitHub metrics` 在 2026-11-25 失败，`Validate catalogue` 仍通过。失败信息为 `gh: Could not resolve to a Repository with the name 'FlowElement-xinliuyuansu/m_flow'.`，即快照脚本无法再取到该仓库；脚本按设计「任一批次失败就保留上一份完整快照」，因此整次刷新中止。

## 1. 移除 M-flow

- 核验：`GET /repos/FlowElement-xinliuyuansu/m_flow` → 404；`GET /orgs/… ` 等价检查显示账户 `FlowElement-xinliuyuansu` 仍存在但 `public_repos = 0`，其下已无公开仓库。
- 搜索 GitHub 只找到第三方同名仓库 `s16173760/m_flow`（描述同为 M-Flow 记忆图框架），所有者不同，不能断言为同一项目，因此不改地址、不替换条目。
- 处理：从 `data/projects.json` 与 `locales/{en,es,hi,fr}/entries.json` 删除该条目（90 → 89 个项目），重新生成五语 `README.md`、`docs/projects.md`、`docs/rankings.md` 与 `data/rankings.csv`。原条目证据固定在提交 `0d585cda2f588af69fb872ae6914caba0c217816`，Apache-2.0，4,508 Stars、最后提交 2026-08-03；本条记录即其留痕，`research/` 台账不改动。

同一次刷新暴露 `unibaseio/membase` 的规范名已变为 `membaseai/membase`，`validate()` 的「显式解析重定向」断言按设计拦下。

- 核验：`GET /repos/membaseai/membase` → 200，MIT，默认分支 `main`，143 Stars，最后推送 2026-11-25；原证据提交 `59100235fa918bdfd19d02b9cf06fac178a839cb` 在新所有者下仍可取到（GitHub 更名保留历史）。
- 处理：`data/projects.json` 的 `repo`、`evidence[].url`、`license_review.source` 全部改为 `membaseai/membase`；四个 locale 的 `entries.json` 键同步改名。
- 显示名回到官方 README 的 `<h1>Membase</h1>`（证据提交与当前 main 均如此），先前写作 `Membase · unibase` 是旧所有者名，已去掉；`boundary` 里「与 `memodb-io/Memobase` 不同」的区分仍然成立，保留。

## 3. 刷新脚本口径变更（同日另行落地）

用户同时选择：仓库明确 404 时不再让整次刷新失败，而是保留该仓库上一份快照记录并标记 `missing_upstream`，其他错误（限流、传输、GraphQL 报错）仍按原规则中止并保留旧快照。该改动与 `docs/methodology.md` 的五语说明一并更新，具体实现以各仓库 `scripts/refresh_metrics.py` 为准。
